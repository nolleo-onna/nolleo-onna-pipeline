# 놀러온나 — 서비스 제안서

> 한국관광공사 TourAPI 기반 부산 청년 여행 코스 추천 서비스

---

## 1. 서비스 개요

부산에 놀러 갈 때 어디부터 가야 할지 막막한 청년을 위해, 지역·시간·동행·분위기 입력 한 번으로 하루 코스를 추천해주는 서비스.

휴무·날씨·혼잡·축제 같은 상황 변수를 자동으로 반영해서 "갔는데 닫혀있더라" 같은 경험을 줄이는 것이 목표.

---

## 2. 문제 정의

부산 여행을 준비할 때 청년 여행자가 자주 겪는 어려움:

- 검색을 2시간 해도 결정이 안 됨 (정보가 흩어져 있음)
- 영업시간 잘못 알고 갔다가 허탕
- 줄 서다 시간 다 보냄
- 비 오면 짠 코스가 다 무너짐
- 부산에 무슨 행사가 있는지 모르고 지나감

기존 서비스들은 식당 위주거나 영상 콘텐츠 중심이라 "오늘 가도 되는 곳"을 데이터로 검증해주지 못한다.

---

## 3. 핵심 기능

### 부산 스팟
부산 관광지·문화시설·음식점을 한 화면에서 탐색.
- 16개 구·군별 필터, 카테고리 필터
- 한국어 부분 검색 + 자연어 의미 검색
- 지도/리스트/코스 뷰 전환
- 영업중 여부, 혼잡도, 실내 여부 표시

### 부산 코스
지역·시간·동행·분위기를 입력하면 하루 코스를 자동 생성.
- 5조건 폼 입력 또는 자연어 입력 ("비 오는 날 혼자 영도 반나절")
- 감성형 / 짠내형 두 가지 코스 동시 추천
- 도착 시각·체류 시간·이동 시간이 표시되는 타임라인
- "왜 이 코스인가요" 사유 표시 (휴무 회피, 비 예보 대응 등)
- 한국관광공사 공식 코스를 가성비 매장으로 재구성하는 "짠내 변환"
- 카카오톡 공유 (공유받은 사람은 로그인 없이도 열람 가능)

### 여행 한끗
부산 여행 전 알면 좋은 정보를 카테고리별로 정리.
- 행사 모음, 무료로 즐기기, 이동 팁, 로컬 꿀팁
- 다가올 행사를 자동으로 큐레이션 후보로 등록 (관리자 검토 후 게시)

### 마이페이지
- 북마크와 컬렉션 (스팟·코스·행사·한끗을 폴더로 정리)
- 방문 이력, 내 리뷰, 내 코스
- 북마크한 스팟 휴무 알림, 행사 임박 알림

## 4. 데이터 활용

| 데이터 소스 | 활용 |
|---|---|
| 한국관광공사 TourAPI | 관광지·문화시설·음식점·행사·여행코스·혼잡도 예측 |
| 행정안전부 착한가격업소 | 부산 가성비 매장 |
| 카카오 OpenAPI | 좌표 보충, 길찾기 |
| 기상청 단기예보 | 시군구 단위 날씨 |

수집한 데이터는 LLM으로 가공해서 활용:
- 영업시간 자유 텍스트를 구조화된 형식으로 정규화
- 스팟 소개글 요약 및 분위기 태그 추출
- 임베딩 생성으로 자연어 검색 지원

---

## 5. 기술 아키텍처

### 분리 구조
```
[Python 데이터 파이프라인]
  외부 API 수집 → 정제 → LLM 가공 → 임베딩 → DB 적재

[Spring Boot 백엔드]
  사용자 인증, 코스 생성·검색·추천, 사용자 데이터 CRUD

[클라이언트]
  PWA (웹/모바일 동시 지원)
```

수집과 서비스를 분리해서 외부 API 장애가 사용자 경험에 영향을 주지 않도록 했고, 임베딩·LLM 파이프라인이 풍부한 파이썬 생태계를 활용했다.

### 데이터베이스
- PostgreSQL 16+ on AWS RDS
- 확장: PostGIS (공간 검색), pgvector (의미 검색), pg_trgm (한글 부분 검색)

### LLM
- OpenAI text-embedding-3-small (의미 검색)
- OpenAI gpt-4o-mini (요약·태그·영업시간 정규화)

## 6. 사용자 시나리오

### 시나리오 1. 부산 첫 방문, 반나절만 있는 여행자

**상황**
서울에서 부산으로 1박 2일 출장 온 26살 직장인. 일정이 비는 토요일 오후 4시간을 어떻게 쓸지 막막하다. 네이버 블로그·인스타·유튜브를 한 시간째 보고 있지만 정보가 흩어져 있어 결정이 안 된다.

**예상 페인포인트**
- 검색은 했는데 코스로 묶기가 어려움
- 어렵게 정한 곳이 휴무거나 영업 종료라 헛걸음
- 도착해보니 줄이 너무 길어서 다음 일정이 다 밀림

**사용 흐름**
1. 놀러온나 접속 → 카카오 로그인
2. "부산 코스" 탭에서 지역(광안리), 시간(반나절), 동행(혼자), 분위기(감성·바다) 선택
3. 추천받은 코스 2개 중 마음에 드는 쪽 선택
4. 코스 상세에서 도착 시각·체류 시간·이동 시간 확인
5. 카카오톡으로 본인에게 공유해두고 출발

**놀러온나가 막아준 것**
- 토요일 점심 피크 시간에 광안리 인기 식당이 혼잡도 80% 예측 → 비교적 한산한 인근 매장으로 자동 대체
- 코스에 포함된 카페가 매주 화요일 휴무인데 오늘은 토요일이라 OK 표시
- 코스 상단에 "토요일 점심 인기 식당 1곳 혼잡으로 대체했어요" 메시지 표시

---

### 시나리오 2. 비 오는 날 혼자 영도

**상황**
22살 대학생. 친구가 약속을 갑자기 취소해서 혼자 영도에 가기로 했다. 일기예보를 보니 오후부터 비. 흰여울문화마을·절영해안산책로 같은 야외 코스를 짜뒀는데 비 오면 다 무너진다.

**예상 페인포인트**
- 비 오면 야외 코스를 어떻게 바꿔야 할지 막막
- 실내로 가도 혼자 가기 어색한 곳이 많음
- 이미 카페 한 군데에서 시간 다 보내게 됨

**사용 흐름**
1. 자연어 입력: "비 오는 날 혼자 영도 3시간"
2. 시스템이 기상청 예보 자동 조회 → 오후 비 80% 확인
3. 실내 위주 코스 추천 (현대미술관 → 카페 → 실내 전시)
4. "혼자" 동행 태그가 매칭된 조용한 분위기 스팟 우선 배치
5. 코스 상세 상단에 "오후 비 예보로 야외 스팟 2개 제외했어요" 표시

**놀러온나가 막아준 것**
- 비 예보를 코스 생성 시점에 자동 반영
- 혼자 가기 어색한 가족 단위 식당 회피
- 사용자가 마지막에 들를 곳이 정말 영업중인지 영업시간 자동 검증

### 시나리오 3. 자연어 검색으로 분위기 찾기

**상황**
24살 여행 좋아하는 사람. 인스타에서 본 "고즈넉한 카페" 같은 분위기를 찾고 싶은데 검색 키워드가 뭔지 모르겠다. 네이버에 "고즈넉한 카페 부산"이라고 쳐도 광고만 잔뜩 나옴.

**예상 페인포인트**
- 키워드를 바꿔가며 검색해도 같은 결과
- 상호명에 "고즈넉"이 들어간 가게만 나오고 분위기는 다름
- 정작 비슷한 분위기의 "조용한"·"한적한" 카페는 놓침

**사용 흐름**
1. 부산 스팟 검색바에 "고즈넉한 카페 야경" 입력
2. 시스템이 자연어를 임베딩 → 의미적으로 가까운 분위기 태그 매칭
3. "조용한"·"한적한"·"분위기 있는" 태그 카페 + 야경 가능 스팟 결합 추천
4. 결과 카드에서 마음에 드는 곳을 북마크 → "가보고싶음" 폴더에 저장

**놀러온나가 막아준 것**
- 키워드 일치가 아닌 의미 일치로 검색
- 사용자가 모르던 후보군 발견

### 시나리오 4. 5만원 예산 데이트, 어디서 줄여야 하지?

**상황**
27살 직장인 커플. 부산에서 데이트하는데 둘이 합쳐 5만원. 보통 점심 한 끼에 3만원 쓰고 나면 카페·관광은 다 포기한다.

**예상 페인포인트**
- 예산 안에서 코스를 짜는 게 어려움
- 가성비 좋은 곳을 몰라서 비싼 관광객 식당으로 가게 됨
- 마지막 코스에서 돈이 모자라 포기

**사용 흐름**
1. 부산 코스 입력 (광안리·5만원·하루·연인·바다·감성)
2. 추천 결과로 두 가지 코스 동시 제공
   - 감성형: 분위기 좋은 카페 중심, 총 4만 8천원
   - 짠내형: 부산 착한가격업소 식당 + 무료 야경, 총 2만 2천원, 절약 2만 8천원
3. 짠내형 코스에서 식당이 부산 인증 가성비 매장이라는 표시 확인
4. 카카오톡으로 상대방에게 공유

**놀러온나가 막아준 것**
- 예산을 미리 분배해서 마지막 코스 포기 상황 예방
- 부산 착한가격업소를 자동 매칭해 가성비 옵션 제공
- 무료 스팟(광안대교 야경 등)을 코스에 자연스럽게 포함

---

### 시나리오 5. 시즌 행사를 우연히 발견

**상황**
30살 부산 거주 직장인. 오랜만에 광안리에 친구 만나러 가는데 마침 그날이 부산국제영화제 기간인 줄 모르고 일반 코스로 갔다가 끝나고 알게 됨.

**예상 페인포인트**
- 부산에 무슨 행사가 있는지 알 길이 없음
- 일정 다 짜고 나서야 시즌 행사 발견
- 행사장 근처에서 무엇을 추가로 즐길지 모름

**사용 흐름**
1. 홈 화면 "오늘 부산 행사" 캐러셀에서 광안리 불꽃축제 D-3 배너 확인
2. 행사 상세 페이지에서 시간·장소·예상 혼잡도 확인
3. 행사 북마크 → 행사 임박 알림 설정
4. 같은 날 부산 코스 생성 시 시스템이 행사를 코스에 자동 삽입 검토
5. "이날 광안리에서 불꽃축제가 열려요, 야경 코스로 추가했어요" 메시지

**놀러온나가 막아준 것**
- 시즌 행사를 능동적으로 알려줌
- 행사 + 일반 코스를 자동 결합
- 알림으로 행사 당일 잊지 않도록 리마인드

### 시나리오 6. 한국관광공사 공식 코스, 청년 예산으로 재구성

**상황**
23살 대학생. 한국관광공사가 추천하는 "해운대 1일 코스"를 따라가보려 했는데 코스 안의 식당이 1인 5만원짜리. 청년 예산엔 부담스럽다.

**예상 페인포인트**
- 공식 추천 코스의 식당이 너무 비쌈
- 그렇다고 직접 짜자니 어디를 바꿔야 할지 모름
- 동선은 지키고 가격만 낮추고 싶음

**사용 흐름**
1. 공식 코스 목록에서 "해운대 1일 코스" 선택
2. 코스 상세에서 "짠내 버전으로 변환" 버튼 클릭
3. 시스템이 코스 안의 음식점을 부산 착한가격업소로 자동 대체
4. "공식 코스 대비 X원 절약, 부산 착한가격업소 N곳 포함" 표시
5. 변환된 코스를 마이페이지에 저장

**놀러온나가 막아준 것**
- 공식 코스의 동선과 컨셉은 유지하면서 가격만 조정
- 부산 인증 가성비 매장을 자동 매칭
- 변환 전후 비교를 명시적으로 보여줌

### 시나리오 7. 트렌드 발견과 타이밍

**상황**
25살 카페 다니기 좋아하는 사람. SNS에서 핫한 카페를 가보고 싶은데, 가보면 이미 사람이 너무 많아서 1시간 대기. 정작 한 달 전이면 한산했다는 후기를 보고 늦었다고 후회.

**예상 페인포인트**
- 뜨는 곳을 알았을 땐 이미 늦음
- 갔더니 너무 혼잡해서 분위기를 못 즐김
- "지금이 갈 타이밍"인 곳을 어떻게 찾는지 모름

**사용 흐름**
1. 홈 화면 "지금이 갈 타이밍" 캐러셀 확인
2. 트렌드는 상승 중인데 오늘은 한산한 카페 발견
3. "최근 1주간 방문자 50% 급증, 오늘은 한산해요" 메시지 표시
4. 스팟 상세에서 트렌드 그래프 + 오늘 혼잡도 확인 후 출발

**놀러온나가 막아준 것**
- 한국관광공사 혼잡도 예측 데이터를 트렌드 발견에도 활용
- "유명해지기 전에 가는" 경험을 데이터로 가능하게 함

### 시나리오 8. 다녀온 곳 기록과 재방문

**상황**
28살 부산 자주 가는 사람. 좋았던 곳을 메모장에 적어두는데 나중에 보면 어디였는지 기억이 안 난다. 친구가 "부산 어디 좋았어?"라고 물어볼 때 답하기 어려움.

**예상 페인포인트**
- 다녀온 곳을 따로 정리하는 게 번거로움
- 시간이 지나면 어떤 분위기였는지 잊어버림
- 친구에게 추천하려 해도 기억이 흐릿

**사용 흐름**
1. 다녀온 스팟에서 한줄 리뷰 + 별점 작성
2. 시스템이 자동으로 방문 이력에 기록 (`VISIT_HISTORY`)
3. 마이페이지 → 방문 이력에서 시간순 정리
4. 친구에게 추천할 때 컬렉션을 만들어 공유
5. 누적된 방문·북마크 데이터로 "내 취향 코스" 추천 활성화

**놀러온나가 막아준 것**
- 리뷰 작성으로 자연스럽게 방문 이력 누적
- 사용자 본인의 취향 데이터화
- 컬렉션 공유로 친구에게 큐레이션 전달

## 7. 기대 효과

### 사용자
- 검색 반복 없이 한 번의 입력으로 검증된 하루 코스
- 휴무·혼잡·날씨 자동 반영으로 실패 줄어듦
- 추천 근거가 보이는 신뢰감

### 지역
- 관광객 동선이 유명 관광지에서 로컬 스팟으로 분산
- 부산 착한가격업소 방문 유입 채널
- 부산관광공사·지자체와 데이터 협력 가능성

### 공공
- 한국관광공사 TourAPI를 의사결정 도구로 가공한 사례
- 자유 텍스트 공공 데이터를 LLM으로 보완한 레퍼런스
- 외국어 TourAPI 연동으로 K-관광 글로벌 확장 기반

## 8. 발전 로드맵

### 1단계 (~6개월): 부산 검증
- 부산 16개 구·군 데이터 통합
- 코스 추천 알고리즘 안정화
- MAU 5,000명 달성

### 2단계 (~1년): 개인화
- 사용자 활동 기반 개인화 추천
- 자연어 검색 고도화
- 한끗 일반 유저 작성 허용

### 3단계 (1년 이후): 확장
- TourAPI 영문/중문/일문 연동
- 부산 → 제주·강원·경주 복제
- 부산관광공사 등 데이터 협력

## 10. 인증·권한

비로그인 사용자도 콘텐츠 열람(스팟·공식 코스·공유 코스·한끗·행사)은 가능하지만, 코스 생성·북마크·리뷰 등 개인화 기능은 카카오/네이버/구글 소셜 로그인이 필요하다.

LLM 비용 보호를 위해 코스 생성은 사용자당 시간당 5회로 제한.
